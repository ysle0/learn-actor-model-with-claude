# 07. Real-time Game - 실시간 게임서버 적합성 분석

> 실시간 게임(FPS, MOBA, MMO 등)에서 Actor Model의 적합성을 분석합니다.

## 한 줄 요약

**Actor Model은 실시간 게임에 적합하지만, 고빈도 업데이트(60fps 물리)는 별도 처리 필요**

```
┌─────────────────────────────────────────────────────────────────┐
│                 Actor Model이 적합한 영역                        │

│     ─────────────────                                           │

│     ─────────────────                                           │

│     ───────────                                                 │
│     • 리더보드, 통계, 업적                                      │

│                                                                 │
```

### ⚠️ 주의가 필요한 영역

```
┌─────────────────────────────────────────────────────────────────┐
│                 주의가 필요한 영역                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 고빈도 물리 시뮬레이션 (60fps+)                             │
│     ─────────────────────────────                               │
│     문제: 초당 60개 메시지 × 1000 엔티티 = 60,000 msgs/sec      │
│     해결: 물리 엔진을 별도 시스템으로 분리                       │
│                                                                 │
│     ┌─────────────────┐                                        │
│     │  Physics Engine │  ← 단일 스레드, 동기 처리               │
│     │  (ECS 패턴)     │                                        │
│     └────────┬────────┘                                        │
│              │ 결과 전달                                        │
│              ▼                                                  │
│     ┌─────────────────┐                                        │
│     │   Game Actor    │  ← 결과를 Actor로 전파                  │
│     └─────────────────┘                                        │
│                                                                 │
│  2. 실시간 위치 동기화                                          │
│     ─────────────────                                           │
│     문제: 모든 이동을 Actor 메시지로 처리하면 병목               │
│     해결: Zone Actor가 배치로 처리, 또는 전용 동기화 레이어     │
│                                                                 │
│  3. 대규모 브로드캐스트                                         │
│     ─────────────────                                           │
│     문제: 1000명에게 브로드캐스트 = 1000개 메시지                │
│     해결: 멀티캐스트 그룹, Pub/Sub 패턴                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### MOBA 게임

```cpp
// MOBA: Zone Actor가 게임 로직 중앙 관리
class MOBAGameActor : public Actor {
    std::vector<Hero> heroes;
    std::vector<Minion> minions;
    std::vector<Tower> towers;

    void on_tick(float delta) {
        // 동기적으로 모든 유닛 업데이트 (60fps)
        for (auto& hero : heroes) {
            hero.update(delta);
        }
        for (auto& minion : minions) {
            minion.update(delta);
        }

        // 충돌 검사
        check_collisions();

        // 상태 변경 브로드캐스트 (20fps로 제한)
        if (should_broadcast()) {
            broadcast_state_to_players();
        }
    }

    // 플레이어 입력은 메시지로 받음
    void receive(PlayerInput input) {
        heroes[input.hero_id].queue_action(input.action);
    }
};
```

## 레이턴시 최적화 전략

### 1. 메시지 배치 처리

```csharp
// 개별 메시지 대신 배치로 전송
public class OptimizedZoneActor
{
    private readonly Dictionary<string, List<GameEvent>> _playerEvents = new();
    private readonly Timer _batchTimer;

    public OptimizedZoneActor()
    {
        // 50ms마다 배치 전송 (20Hz)
        _batchTimer = new Timer(FlushEvents, null, 50, 50);
    }

    private void FlushEvents(object _)
    {
        foreach (var (playerId, events) in _playerEvents)
        {
            if (events.Count > 0)
            {
                SendBatchToPlayer(playerId, events);
                events.Clear();
            }
        }
    }
}
```

### 2. 예측 및 보간

```
클라이언트 측 예측 (Client-Side Prediction)
──────────────────────────────────────────
입력 → 즉시 로컬 적용 → 서버 확인 → 보정

서버 권위 모델
──────────────
입력 → 서버 전송 → 서버 처리 → 결과 수신 → 보간 적용

Actor에서의 구현:
- PlayerInputActor: 입력 수신 및 검증
- GameStateActor: 권위적 상태 관리
- SyncActor: 클라이언트 동기화
```

### 3. 관심 영역 (AOI) 최적화

```cpp
// 시야 범위 내의 엔티티만 업데이트
class ZoneActor {
    spatial_hash<Entity> entities;

    void broadcast_movement(Entity& mover) {
        // O(n²) 대신 O(k) - k는 근처 엔티티 수
        auto nearby = entities.query_radius(
            mover.position,
            VIEW_RADIUS
        );

        for (auto& entity : nearby) {
            if (entity.is_player()) {
                entity.send(movement_update{mover});
            }
        }
    }
};
```
