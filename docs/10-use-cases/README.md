# 10. Actor Model 사용 케이스

> 실제 프로덕션 환경에서 Actor Model이 활용되는 다양한 분야와 사례

## 개요

Actor Model은 1973년 Carl Hewitt에 의해 제안된 이후, 다양한 산업 분야에서 대규모 분산 시스템의 핵심 아키텍처로 채택되어 왔습니다. 이 문서에서는 실제 프로덕션 환경에서 Actor Model이 어떻게 활용되고 있는지 살펴봅니다.

## 산업별 사용 케이스

### 1. 통신 (Telecommunications)

#### Ericsson - Erlang의 탄생

```
┌─────────────────────────────────────────────────────────────┐
│                    Ericsson AXD 301                          │
│                 (ATM 스위치 시스템)                          │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐    │
│   │ Call    │   │ Call    │   │ Call    │   │ Call    │    │
│   │ Handler │   │ Handler │   │ Handler │   │ Handler │    │
│   │ Actor   │   │ Actor   │   │ Actor   │   │ Actor   │    │
│   └────┬────┘   └────┬────┘   └────┬────┘   └────┬────┘    │
│        │             │             │             │          │
│   ┌────┴─────────────┴─────────────┴─────────────┴────┐    │
│   │              Supervisor Tree                       │    │
│   └───────────────────────────────────────────────────┘    │
│                                                              │
│   • 99.9999999% 가용성 (Nine Nines)                         │
│   • 연간 31ms 미만의 다운타임                               │
│   • 수백만 동시 통화 처리                                    │
└─────────────────────────────────────────────────────────────┘
```

**주요 특징:**
- 각 전화 통화가 독립적인 Actor (프로세스)
- 통화 실패 시 해당 Actor만 재시작
- 시스템 전체 중단 없이 코드 업데이트 (Hot Code Swapping)
- 수백만 개의 경량 프로세스 동시 실행

**상세 문서:** [통신 시스템 케이스](./telecommunications.md)

## 기술적 장점 요약

| 분야 | 핵심 이점 | 주요 프레임워크 |
|------|----------|----------------|
| 통신 | 고가용성, 무중단 업데이트 | Erlang/OTP |
| 게임 | 대규모 동시성, 실시간 처리 | Orleans, Akka |
| 금융 | 이벤트 소싱, 감사 추적 | Akka, Axon |
| 스트리밍 | 세션 관리, 스케일링 | Akka, Elixir |
| IoT | 디바이스 격리, Digital Twin | Akka, Orleans |
| 소셜 | 메시지 라우팅, 연결 관리 | Erlang/OTP |
| 전자상거래 | 분산 트랜잭션, 상태 관리 | Akka, Orleans |

## 공통 성공 요인

### 1. Actor 단위 격리

```
┌─────────┐   장애   ┌─────────┐   정상   ┌─────────┐
│ Actor A │ ───X───▶│ Actor B │ ───────▶│ Actor C │
└─────────┘         └─────────┘         └─────────┘
     ↓                                       ↑
   재시작                                   영향 없음
```

### 2. 위치 투명성

```
로컬 호출과 원격 호출이 동일한 인터페이스:
  actor.send(message)  // 로컬이든 원격이든 동일
```

### 3. 탄력적 스케일링

```
부하 증가 시:
  [Actor] → [Actor, Actor, Actor] → [Actor, Actor, Actor, Actor, Actor]
```
