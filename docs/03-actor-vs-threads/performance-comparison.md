# 성능 비교

> Thread 모델과 Actor Model의 성능 특성 비교

## 메모리 사용량

### 스레드 vs Actor

```
┌─────────────────────────────────────────────────────────────────┐
│                    Memory Footprint                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   OS Thread:                                                     │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │  Stack Size: 1MB ~ 8MB (플랫폼 의존)                     │   │
│   │  + Thread Control Block                                  │   │
│   │  + Kernel structures                                     │   │
│   │  ─────────────────────────────────────────────           │   │
│   │  총: 약 1MB ~ 10MB per thread                           │   │
│   └─────────────────────────────────────────────────────────┘   │
│                                                                  │
│   Actor (Erlang Process):                                        │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │  Initial heap: 233 words (~1.8KB on 64-bit)              │   │
│   │  Mailbox: 동적 할당                                      │   │
│   │  Stack: 동적 확장                                        │   │
│   │  ─────────────────────────────────────────────           │   │
│   │  총: 약 2KB ~ 10KB per actor                            │   │
│   └─────────────────────────────────────────────────────────┘   │
│                                                                  │
│   비율: Actor가 약 100~1000배 적은 메모리 사용                  │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 동시 연결 수

```
서버 메모리: 16GB

Thread 기반:
  16GB / 1MB = 약 16,000 스레드

Actor 기반:
  16GB / 5KB = 약 3,200,000 액터

→ Actor 모델이 200배 더 많은 동시 연결 처리 가능
```

```

├─────────────────────────────────────────────────────────────────┤
│                                                                  │

│   3. 페이지 테이블 전환 (프로세스 간)                           │

│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### Actor 스위칭

```
┌─────────────────────────────────────────────────────────────────┐
│              Actor Message Processing Switch                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   수행 작업:                                                     │
│   1. 현재 메시지 처리 완료                                      │

│   3. 메시지 핸들러 호출                                         │
│                                                                  │
│   비용: 수십-수백 나노초                                        │
│                                                                  │
│   Erlang 예: ~0.5 마이크로초 (thread 대비 10-20배 빠름)         │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────────────────────┐
│        High Contention Scenario Performance                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
```

## 확장성 (Scalability)

### 스레드 수 증가에 따른 성능

```
┌─────────────────────────────────────────────────────────────────┐
│            Scalability: Threads vs Actors                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   처리량                                                         │
│     ▲                                                           │
│     │                    ──────── Actor Model                   │
│     │              ─────                                        │
│     │         ────                                              │
│     │      ───           ┌─────── Thread Model (Lock)           │
│     │   ───              │                                      │
│     │  ─      ───────────┘                                      │
│     │ ─  ────            ↘ Lock Contention                     │
│     │────                                                       │
│     └─────────────────────────────────────────▶ 동시성 수준     │
│        1    10    100   1000  10000                             │
│                                                                  │
│   스레드 증가 시:                                                │
│   • Lock 모델: 일정 수준 이후 성능 저하                         │
│   • Actor 모델: 선형적 확장                                     │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## 실제 사례 벤치마크

### WhatsApp (Erlang)

```
서버당 처리량:
• 200만 동시 연결
• 초당 수십만 메시지
• 서버 32대로 4.5억 사용자 서비스

비결:
• 경량 Erlang 프로세스 (Actor)
• Lock-free 메시지 패싱
• Supervision을 통한 장애 복구
```

### Discord (Elixir/Erlang)

```
• 1100만 동시 사용자
• 초당 수백만 이벤트
• 밀리초 단위 메시지 전달

아키텍처:
• Guild = Erlang Process (Actor)
• 메시지 브로드캐스트 최적화
• 수평 확장 용이
```
